# AXI DMA Subsystem Coverage Waiver Rationale

## 1. Scope

This document explains the reviewed exclusions stored in:

```text
sim/exclusions/subsystem_unreachable.el
```

The checked-in `.el` file contains 6 line-block, 22 condition, 170 toggle, 2 FSM-transition, and 2 branch directives.

The file applies only to structural code coverage for the configured subsystem RTL. Assertions and functional covergroups are reported but are never waived by this file.

The current `.el` contains the following exclusion directives:

| Metric/object type | Directives | Meaning |
|---|---:|---|
| Line (`Block`) | 6 | Unreachable statements in the integrated command/abort handshake. |
| Condition | 22 | Impossible Boolean vectors created by prerequisite or direct-handshake relationships. |
| Toggle | 170 | Constant, statically assigned, alignment, width, address-window, or protocol-configuration bits. A directive may cover a bit range. |
| FSM transition | 2 | One impossible direct transition in each channel manager FSM. |
| Branch | 2 | Unreachable inner/default alternatives. |

These are not waivers for observed failures. They are coverage-object exclusions supported by configuration or temporal reachability evidence.

## 2. Application policy

The launcher applies the file through URG as follows:

```bash
urg -dir <merged.vdb> \
  -metric line+cond+tgl+fsm+branch+assert+group \
  -elfile sim/exclusions/subsystem_unreachable.el \
  -excl_strict \
  -report <report-directory>
```

The sign-off flow applies `-excl_strict`. The `.el` contains module checksums and object IDs tied to the source and elaboration; a checksum mismatch stops the exclusion file from applying.

The reviewed file was also cleaned against `attempts.log`. Exclusions that referred to already-covered objects were removed. This avoids the URG warning that attempts to exclude covered objects were ignored.

## 3. Line exclusions

### 3.1 `dma_desc_manager`

Five statements are excluded:

| Statement family | Reason |
|---|---|
| Abort classification while in `ST_VALIDATE` | `ST_VALIDATE` lasts one clock. A second software abort cannot traverse the subsystem AXI-Lite path and commit before the manager advances. |
| Abort exactly coincident with route or descriptor READY acceptance | These branches require a registered software abort on the exact internal handshake edge. That edge cannot be deterministically scheduled from the public AXI-Lite interface. Forcing it would validate a testbench-created state rather than a legal integrated transaction. |
| Direct completion from `ST_ISSUE_RD_DESC` | `rd_status_accept` requires `rd_desc_issued_reg`, which is set only on the edge that leaves `ST_ISSUE_RD_DESC`; therefore direct completion on that edge is impossible. |

### 3.2 `dma_ctrl_regs`

One `cmd_valid <= 0` statement is excluded. In the integrated design, `cmd_valid` and `cmd_ready` are directly coupled to the manager. The state needed for an unaccepted pending command while both `pending_cmd_accept` and `busy_i` are low cannot occur.

## 4. Condition exclusions

### 4.1 `dma_ctrl_regs`

Seventeen condition vectors are excluded in the following families:

| Condition family | Unreachable relationship |
|---|---|
| `aw_hold_valid && w_hold_valid` | The configured AXI-Lite crossbar does not forward local WVALID before AW has decoded a target. The missing vector is an integration constraint, not an untested legal sequence. |
| `write_commit && ...` combinations | `write_commit` is defined from both hold-valid terms and the absence of an outstanding B response. Vectors that make a prerequisite false while the compound expression is true contradict the RTL definition. |
| `cmd_valid && cmd_ready` combinations | The register block creates `cmd_valid` only when the directly connected manager can accept it; reset clears both. The missing independent vector is not reachable. |
| START/ABORT/CLEAR write predicates | A compound register-write action cannot be true when `write_commit`, `write_valid`, selected address, WSTRB, or the selected data bit is false. |
| `busy_i || cmd_valid || pending_cmd_accept` | `pending_cmd_accept` equals `cmd_valid && cmd_ready`, so it cannot assert by itself or while `cmd_valid` is zero. |
| `cmd_valid && !pending_cmd_accept && !busy_i` | The direct manager handshake makes the remaining pending/busy truth-table vectors temporally contradictory. |

### 4.2 `dma_irq_status_ctrl`

Five condition vectors are excluded. IRQ writes are accepted only when the compound write predicate, address selection, and data/strobe prerequisites agree. Missing vectors that make an inner action true while `write_valid` or its address prerequisite is false cannot be generated by the RTL.

## 5. FSM exclusions

Both channel FSMs exclude the same transition:

```text
ST_ISSUE_RD_DESC -> ST_COMPLETE
```

The legal flow is `ST_ISSUE_RD_DESC -> ST_WAIT_STATUS -> ST_COMPLETE`. `rd_status_accept` depends on the registered `rd_desc_issued_reg`, which becomes true only when the FSM leaves `ST_ISSUE_RD_DESC`. Consequently, the direct transition cannot be taken for either channel.

All reachable states and remaining arcs are covered; the waived direct arcs are why the reviewed FSM result is 100%.

## 6. Branch exclusions

Two `dma_ctrl_regs` branches are excluded:

| Branch | Reason |
|---|---|
| Inner pending-command-only abort path | The integrated direct command-manager handshake cannot retain a pending-only command in the state required by this inner alternative. |
| Register-write case default under `write_valid` | `write_valid` is false for addresses that would select the default case, so the enclosing predicate prevents entry. Invalid local offsets are still verified externally and return SLVERR. |

## 7. Toggle exclusions by module

### 7.1 `axi_dma_subsystem_core`

The core section contains 102 grouped toggle directives. They fall into the following reviewed families.

#### AXI-Lite address alignment and local response encoding

| Signals | Excluded bits | Reason |
|---|---|---|
| `s_axil_awaddr`, `s_axil_araddr` | `[1:0]` | All software accesses are 32-bit aligned. |
| `axil_m_awaddr`, `axil_m_araddr` | low two bits in each packed local lane | Each local AXI-Lite block receives word-aligned addresses. Covered higher bits were removed from the waiver. |
| `ctrl_awaddr`, `ctrl_araddr`, `irq_awaddr`, `irq_araddr` | low two bits of each packed local lane | Each channel/global local address is word aligned; ranges such as `[13:12]` are the low bits of the second packed channel lane. |
| `axil_m_bresp`, `axil_m_rresp`, `ctrl_bresp`, `ctrl_rresp`, `irq_bresp`, `irq_rresp` | response bit 0 of local lanes | Local targets generate OKAY (`00`) or SLVERR (`10`), so bit 0 remains zero. Top-level DECERR behavior is tested separately. |

#### Memory-window address constants

| Signals | Excluded bits | Reason |
|---|---|---|
| `m_axi_mem_awaddr`, `m_axi_mem_araddr` | target-lane bits `[27:16]`, `[31:29]` and corresponding packed RAM1 lane positions | Each output lane is confined to one 64-KiB target. Address bit 28 selects RAM1; the remaining upper bits are target constants. |
| `axi_m_awaddr`, `axi_m_araddr` | same target-window upper ranges | These are the internal aliases of the same decoded memory-side addresses. |
| `axi_s_awaddr`, `axi_s_araddr` | aligned low bits for the DMA source lanes | DMA commands are word aligned because unaligned support is disabled. External master address bits that are programmable and reachable are covered, not waived. |

#### AXI size, lock, burst, cache, protection, and ID configuration

| Signals | Excluded fields | Reason |
|---|---|---|
| `s_axi_ext_awsize`, `s_axi_ext_arsize`, `m_axi_mem_awsize`, `m_axi_mem_arsize`, `axi_m_awsize`, `axi_m_arsize` | SIZE bit 2 in the affected 32-bit lanes | A 32-bit data bus supports 1-, 2-, or 4-byte beats; SIZE bit 2 is always zero. |
| `s_axi_ext_awlock`, `s_axi_ext_arlock`, `m_axi_mem_awlock`, `m_axi_mem_arlock`, `axi_m_awlock`, `axi_m_arlock` | all instantiated lock bits | Exclusive/locked transfers are outside this subsystem configuration; all masters use NOLOCK. |
| `dma_axi_awid`, `dma_axi_arid` and low packed `axi_s_*id` lanes | DMA-lane IDs | DMA AXI IDs are fixed by channel/configuration rather than software programmable. External ID values are exercised. |
| `dma_axi_awsize`, `dma_axi_arsize` and corresponding DMA slices in `axi_s_*size` | fixed `SIZE=010` bits | DMA wrappers always transfer 4-byte beats. |
| `dma_axi_awburst`, `dma_axi_arburst` and corresponding low `axi_s_*burst` slices | fixed INCR encoding | DMA-generated bursts are INCR. External FIXED/INCR/WRAP traffic is exercised rather than waived. |
| `dma_axi_awcache`, `dma_axi_arcache` and low `axi_s_*cache` slices | fixed `CACHE=0011` bits | DMA wrapper attributes are configuration constants. |
| `dma_axi_awprot`, `dma_axi_arprot` and low `axi_s_*prot` slices | fixed `PROT=010` bits | DMA wrapper attributes are configuration constants. |
| low DMA slices of `axi_s_awlen`, `axi_s_arlen` | upper LEN bits | DMA burst length is limited to 16 beats. External masters cover longer legal INCR traffic. |

#### Command, descriptor, completion, route, ID, and USER fields

| Signals | Excluded bits | Reason |
|---|---|---|
| `cmd_payload[0].src_ch` | channel-owner bit | Lane 0 is statically bound to CH0. |
| `cmd_payload[0].src_addr`, `cmd_payload[1].dst_addr` | alignment bits | DMA addresses are aligned with `ENABLE_UNALIGNED=0`. |
| `completion[0/1].completed_len` | `[19:17]` | A legal transfer cannot exceed one 64-KiB RAM window. Length bit 16 is exercised by the legal-extent test. |
| `completion[0].hw_tag[7]` | owner/tag high bit | Completion lane 0 is permanently associated with DMA0. |
| `completion[0].owner_ch` | owner bit | Each completion array lane is statically assigned to its channel. |
| `route_fault_code` | `[4:0]`, `[7:6]` | The route controller emits the single encoded route-conflict value `0x20`; only the encoding's active bit can toggle. |
| `route_fault_source` | `[1:0]` | Route faults use the fixed ROUTE source encoding `3'b100`. |
| `rd_desc_id`, `wr_status_id`, `axis_read_tid`, `axis_write_tid` | unused ID bits | IDs are derived from the two-channel source assignment; unused upper bits are zero. |
| descriptor/status/AXIS `*_user` | one-bit USER fields | USER is tied to zero end-to-end in this configuration. |

### 7.2 `dma_desc_manager`

Thirteen toggle directives repeat manager-local versions of integration invariants:

- CH0/CH1 lane ownership fixes selected channel bits.
- `cmd_payload` and `cmd_reg` address low bits are word-alignment constants.
- descriptor and status ID bits are statically assigned; unused ID bits remain zero.
- descriptor/status USER fields are tied low.
- completion length bits `[19:17]` cannot be reached by a legal single-window transfer.
- completion lane 0 owner/tag ownership bits are fixed by lane assignment.

### 7.3 `dma_ctrl_regs`

Nine toggle directives cover:

- `s_axil_awaddr[1:0]`, `s_axil_araddr[1:0]`, and `aw_hold_addr[1:0]`: word alignment;
- `s_axil_bresp[0]` and `s_axil_rresp[0]`: OKAY/SLVERR-only local response encoding;
- `completion_i.completed_len[19:17]` and `completed_len_reg[19:17]`: the 64-KiB legal-transfer limit; and
- `cmd_payload.src_addr[1]` and `cmd_payload.dst_addr[1]`: the residual uncovered alignment bit. Address bit 0 was covered and was removed from the exclusion attempt.

### 7.4 `dma_channel_wrap`

Thirty-three directives cover wrapper-level constants:

| Signal family | Reason |
|---|---|
| `rd_desc_addr`, `wr_desc_addr`, `m_axi_awaddr`, `m_axi_araddr` | Low alignment bits and upper bits outside the two 64-KiB windows cannot change for a legal descriptor. Bit 28 selects RAM1. |
| `wr_desc_len`, `wr_status_len` | Bits `[19:17]` exceed the configured single-window legal extent. |
| `m_axi_awlen`, `m_axi_arlen` | Bits `[7:4]` are zero because DMA bursts are at most 16 beats. |
| `rd_desc_id`, `wr_status_id`, read/write AXIS/FIFO TID | IDs are statically derived from the two channel lanes; unused upper bits are zero. |
| `rd_desc_user`, `wr_status_user`, read/write AXIS/FIFO TUSER | USER is tied to zero. |
| `rd_status_error[1]/[3]` | Vendor read status maps only to 0, 4, or 5. |
| `wr_status_error[3]` | Vendor write status maps only to 0, 6, or 7. |

### 7.5 `dma_axis_route_ctrl`

Four directives are present:

- `route_fault_code[4:0]` and `[7:6]`: route faults are fixed to `DMA_ERR_ROUTE_CONFLICT` (`0x20`).
- `route_fault_source[1:0]`: the source is fixed to ROUTE (`3'b100`).
- `idempotent_grant[1]`: after accepting a grant, the manager immediately drops `route_req_valid`; an active same-owner idempotent re-request cannot occur on that lane.

### 7.6 `dma_irq_status_ctrl`

Nine directives cover:

- local AXI-Lite AW/AR and held-address word-alignment bits;
- local B/R response bit 0, which is fixed for OKAY/SLVERR responses;
- completion length bits `[19:17]`, beyond the legal single-RAM extent; and
- completion lane 0 owner/high-tag bits, fixed by static channel ownership.

## 8. What is deliberately not waived

The following remain real coverage targets:

- all functional covergroups;
- all project and vendor assertion activation;
- reachable AXI-Lite AW/W ordering and B/R backpressure;
- programmable EXT0/EXT1 ID, CACHE, PROT, burst, address, and data fields;
- legal tag/counter rollover behavior;
- reachable manager states and FSM arcs;
- legal RAM boundary and full 64-KiB transfers;
- error responses, abort classifications, IRQ masking, reset recovery, and completion reordering; and
- any uncovered object for which reachability has not been proven either way.

These items remain outside the exclusion file.

## 9. Review and maintenance rules

Re-review the exclusion file when any of the following changes:

- `ENABLE_UNALIGNED`, `ENABLE_SG`, data width, ID width, RAM size, or burst limit;
- memory or AXI-Lite address map;
- channel/master/target count;
- descriptor-manager or route-controller timing;
- AXI/AXIS attribute configuration;
- source paths, hierarchy, or elaborated module names; or
- VCS/URG version.

For every new exclusion, retain four pieces of evidence: exact metric object, reachable-state analysis, configuration dependency, and reviewer rationale. If a directed public-interface test can reach the object, add that test instead of a waiver.

Generated full-exclusion templates, waiver generators, and audit logs are not required to run the final regression. The reviewed `subsystem_unreachable.el`, `sim/cm_hier.cfg`, and launcher configuration are required.
